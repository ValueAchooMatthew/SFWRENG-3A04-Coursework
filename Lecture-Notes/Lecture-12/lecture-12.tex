\begin{itemize}
	\item The $4 + 1$ model is composed of 5 distinct views.
	\begin{itemize}
		\item Each view can be expressed with models reflecting their design.
	\end{itemize}
	\item Below is a list of some acceptable models each view in the $4 + 1$ model can use to express their design.
	\begin{enumerate}
		\item The logical view:
		\begin{itemize}
			\item Class diagrams.
			\item Block diagrams.
			\item Sequence diagrams.
			\item Communication diagrams.
		\end{itemize}
		\item The process view:
		\begin{itemize}
			\item Activity diagrams.
			\item Interaction diagrams.
		\end{itemize}
		\item The development view:
		\begin{itemize}
			\item Package diagrams.
		\end{itemize}
		\item The physical view:
		\begin{itemize}
			\item Deployment diagrams.
		\end{itemize}
	\end{enumerate}
	\item `Patterns' are reliable solutions for frequently encountered problems in design.
	\item `Architectural styles' are equivalence classes describing systems which use similar patterns when solving a giving problem.
	%TODO: Verify with slides.
	\item In use case diagrams:
	\begin{itemize}
		\item `Use case controllers' orchestrate what use case (or mode) the system is in.
		\begin{itemize}
			\item Use case controllers can be represented mathematically as Finite State Machines (FSMs)
		\end{itemize}
	\end{itemize}
	\item In class diagrams:
	\begin{itemize}
		\item Boundary classes are interface hiding classes.
	\end{itemize}
\end{itemize}
